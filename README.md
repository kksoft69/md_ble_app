# Android Chrome 오프라인 BLE 앱 시험

## 오프라인 설치

이 폴더의 `index.html`, `styles.css`, `app.js`, `manifest.webmanifest`, `sw.js`,
`icon-192.png`, `icon-512.png`를 **같은 HTTPS 경로**에 게시한다. 최초 설치할 때만 인터넷
연결이 필요하다. 서비스 워커가 이 파일들을 휴대폰에 저장한 뒤에는 인터넷,
Wi-Fi, CM4 연결 없이 앱을 열고 Raytac에 BLE로 직접 연결할 수 있다.

1. Android Chrome에서 HTTPS 앱 주소를 연다. 화면 상단에 **오프라인 실행 준비 완료**가 표시될 때까지 기다린다.
2. **휴대폰에 앱 설치** 버튼을 누른다. 버튼이 보이지 않으면 Chrome 메뉴에서 **앱 설치** 또는 **홈 화면에 추가**를 선택한다.
3. Chrome을 닫고 휴대폰의 Wi-Fi와 모바일 데이터를 모두 끈다. Bluetooth는 켠 상태로 둔다.
4. 홈 화면의 **MD 센서 BLE**를 실행한다. 페이지가 열리고 센서 연결·상태·설정 화면이 보이면 오프라인 캐시가 정상이다.
5. Raytac의 BLE 광고가 이미 ON이면 **센서 연결**을 눌러 데이터를 확인한다.

오프라인에서 앱 자체는 실행되지만, BLE 광고가 OFF인 센서는 휴대폰에서 찾을
수 없다. 이 경우 CM4 대시보드에서 광고를 켜거나 펌웨어 설정을 변경해야 한다.
앱 코드가 업데이트된 경우 인터넷 연결 중 다시 열어 새 파일을 캐시에 받는다.
기존 설치 앱은 새 서비스 워커가 활성화되도록 한 번 더 새로고침하거나 재실행한다.
화면 하단에 `v3`가 표시되면 현재 화면이다.

실시간 탭은 X/Y/Z의 가속도 RMS·P2P, 세 축의 추이 그래프와 상세 통계를 보여준다.
현재 ESP32 펌웨어는 MDV1 패킷의 속도 RMS와 RPM 필드에 항상 0을 넣으므로,
휴대폰 앱은 이 두 항목을 측정값으로 표시하지 않는다.
이벤트 탭은 수신한 이벤트와 XYZ raw 파형 및 CRC 결과를 보여준다.
설정 탭에서 전원 주기와 이상 임계값을 바꿀 수 있다.

## 시작

1. Raytac MTD/FTD의 새 펌웨어를 빌드하고 플래시한다. ESP32, IIS3DWB, UART 배선과 펌웨어는 변경하지 않는다.
2. CM4의 `apps/otbr_dashboard` 코드를 배포하고 서비스를 재시작한다. PC 대시보드에서 대상 센서를 선택해 **BLE 광고 ON**을 누른다. 초기값은 OFF이며 Raytac NVS에 저장된다.
3. `apps/ble_phone` 폴더의 앱 파일 7개를 HTTPS로 제공한다. 예: 별도의 GitHub Pages 저장소 루트에 업로드한다. `file://` 및 CM4의 일반 HTTP 주소는 오프라인 앱 설치 경로로 사용하지 않는다.
4. Android에서 Bluetooth를 켜고 **센서 연결**을 누른다. `MD-VIB`를 선택한다. 여러 센서가 같은 이름이면 Android 선택창의 신호 세기와 접속 후 Device ID를 확인한다.
5. 휴대폰 화면에서 통계, 전압, 이벤트, XYZ raw 파형, 전원 설정, 이상판정 설정을 확인한다. 연결 해제 시 Raytac이 Thread에 다시 참가한다.

## 프로토콜

- GATT service `7a526000-758e-4bf4-a9a0-0a349b8ac001`
- Notify `7a526001-758e-4bf4-a9a0-0a349b8ac001`, Write `7a526002-758e-4bf4-a9a0-0a349b8ac001`
- 각 GATT 조각은 `kind:u8, message_id:u16LE, total:u16LE, offset:u16LE, payload`이다. 기본 23-byte MTU에서도 동작하도록 13-byte 데이터 조각으로 나눈다.
- Notify 종류: 1=기존 MDV1 통계, 2=MDS1 상태, 3=MDA1 이상설정 상태, 4=MDE1 이벤트, 5=MDR1 raw 청크, 6=MDPR 전원응답, 7=MDAR 설정응답, 8=저장 프로필.
- Write 종류: 1=BLE 광고 OFF, 2=기존 MDPC 전원 명령, 3=기존 MDAC 이상설정, 4=저장 프로필 요청. 기존 UART·Thread 패킷 본문을 그대로 재사용한다.
- CM4 제어: `POST /api/ble` 본문 `{"sensor_id":"<16자리 Device ID>","enabled":true|false}`. Raytac CoAP `/ble`은 `MDBL` v1 요청을 받고 `MDBR`로 응답한다. `/ble-status`로 광고 상태를 보고한다.
- 휴대폰에서 바꾼 이상설정은 Thread 복귀 후 Raytac의 `/anomaly-profile` 보고로 CM4 대시보드 설정 DB에 동기화된다.

## 시험 순서

1. 광고 OFF에서 기존 Thread 데이터/대시보드가 계속 동작하는지 확인한다.
2. 광고 ON 후 Android에서 검색되는지 확인한다. 광고 간격은 1.0–1.2초이며 배터리 전류 증가량을 별도로 측정한다.
3. 접속하면 Raytac 로그의 `Thread stopped`, CM4의 해당 센서 오프라인, 휴대폰의 MDV1/MDS1 수신을 확인한다.
   기존 주기동작이 켜져 있었다면 접속 중에는 ESP를 깨워 연속동작으로 전환하고, 휴대폰에서 전원 설정을 변경하지 않은 경우 연결 해제 후 이전 주기로 복구한다.
4. 진동을 일으켜 MDE1 이벤트와 MDR1 XYZ 1024시점 raw, 수신 byte 수와 CRC 결과를 확인한다.
5. 휴대폰에서 전원 주기와 이상 임계값을 변경하고 `ESP 적용 v`가 목표 버전으로 따라오는지 확인한다.
6. 휴대폰에서 연결 해제한 뒤 Thread 재참가와 CM4 대시보드 데이터 복귀를 확인한다.
7. 휴대폰에서 **BLE 광고 OFF**를 누르면 연결이 끊기고 Thread가 복귀한다. CM4에서 연결 중 OFF를 누른 경우는 대기 명령이 연결 해제 후 적용된다.

## 제한 사항

- Raytac이 휴대폰과 연결된 동안 Thread를 정지하므로 CM4에서 그 센서로 즉시 명령을 전달할 수 없다. CM4의 OFF는 메모리에 대기하며, CM4 서비스가 재시작되면 대기 명령은 소실된다. 즉시 종료는 휴대폰의 OFF 또는 연결 해제를 사용한다.
- BLE GATT 제어는 이번 현장 시험용이며 인증·권한 부여가 구현되지 않았다. 배포 전에는 페어링/인증과 설정 권한 설계가 필요하다.
- BLE 광고 및 접속은 SED 전류·Thread 지연에 영향을 줄 수 있다. 실제 전력과 raw 1024시점 전송시간을 측정해야 한다.
- 휴대폰 페이지는 센서에 직접 붙어 표시한다. BLE 연결 중 CM4에는 해당 센서 데이터가 저장되지 않는다.
